# STEP 1 — 現状調査・改修境界（2026-10-18）

## 確認対象
- `index.html`: `month_config.json` からお知らせを取得。個別・一括注文および計算アシスタントへの入口。
- `single.html`: `month_config.json` を取得し、成功時は `salonOrderMasterConfig` に保存。失敗時は保存済みマスタを使用し、なければHTML内の8/9月度内蔵マスタを使用。
- `bulk.html` + `app.js` + `default-master.js`: 予備マスタから開始し、JSON取得成功時に差し替え、失敗時は保存済みマスタに切り替え。
- `calc.html`: 計算アシスタント入口。
- `calc_pt.html`: `month_config.json` を取得しPT最適化計算。
- `calc_split.html`: `month_config.json` を取得し左右分配計算。
- `month_config.json`: activeMonths / products（price、月度別pts）/ newsList。現行は10月度。

## 確認されたリスク
1. JSON取得失敗時に古い月度の商品マスタを使用して注文を作成しうる。
2. single/bulkのフォールバック方式が異なる。
3. HTTPエラー時の取り扱い、JSON構造の妥当性チェック、操作停止が一貫していない。
4. 入力情報保存（会員・配送情報）と商品マスタのキャッシュは目的が違う。前者を誤って削除しないこと。

## 確定した改修方針
- `month_config.json` を唯一の計算用マスタとする。
- 最新データの取得・検証が失敗したら計算・注文書作成を不可にし、再試行を案内する。
- single/bulkの読み込み方法を共通化する。内蔵予備データと商品マスタキャッシュへの依存を撤去する。
- PT最適化と左右分配の計算アルゴリズムは原則変更しない。
- 保存済み会員情報・配送情報など、計算マスタ以外の利便機能は維持する。
- CSS/UIの刷新は別変更として実施し、白・黒・グレーのニュートラルな構造を先に作る。
- 本番mainは変更しない。

## 実装前の検証項目
- JSON取得成功、HTTPエラー、ネットワーク切断、不正JSON、必須項目欠落
- 月度選択・商品単価・PTの反映
- 個別・一括注文の計算結果と注文書出力
- PT最適化・左右分配の改修前後一致
- 保存済み会員情報・配送情報の維持
- モバイル表示と操作
